# Mentat 1.16.0 → 1.18.0 upgrade benchmark — 2026-10-23

The bump takes in the `resolve_avs` fix (Mentat master `6a1b08de2`, released
in `mentatdb` 1.18.0). The fix answers the report in plan task A1: identity
upserts and lookup-refs scanned the whole `all_datoms` view on every lookup,
so saving a large model, and `import-csv` in particular, was quadratic in
its size.

**Setup:**
- 8-core laptop, NixOS, release builds.
- The `improv` CLI was built twice from the same commit: once against
  `mentatdb` =1.16.0 and once against =1.18.0 from crates.io.
- `docs/reviews/bench/bench-mentat.sh old new 3`: 3 rounds, alternating
  A/B order each round. The table shows medians.

| Step | 1.16.0 ms | 1.18.0 ms | Δ | RSS MiB (old / new) |
|---|---:|---:|---:|---|
| import 100k | 23395 | 7299 | −68.8% | 74 / 70 |
| import 200k | 99502 | 16141 | −83.8% | 124 / 120 |
| re-import 100k | 43281 | 9052 | −79.1% | 228 / 228 |
| re-import 200k | 185255 | 21019 | −88.7% | 436 / 436 |
| set one cell 100k | 1335 | 1194 | −10.6% | 206 / 207 |
| set one cell 200k | 3239 | 2823 | −12.8% | 398 / 398 |
| load + list 100k | 588 | 607 | +3.2% | 140 / 141 |
| load + list 200k | 1406 | 1376 | −2.1% | 259 / 260 |
| eval 100k | 729 | 762 | +4.5% | 148 / 150 |
| eval 200k | 1762 | 1703 | −3.3% | 272 / 272 |
| show 100k | 584 | 605 | +3.6% | 140 / 141 |
| show 200k | 1442 | 1390 | −3.6% | 260 / 260 |

**The import, by size** (single runs, `import-csv` of a Time × Product CSV):

| rows | 1.16.0 | 1.18.0 |
|---:|---:|---:|
| 100,000 | 21.5 s | 7.0 s |
| 200,000 | 90.7 s | 15.6 s |
| 400,000 | (~6 min, extrapolated) | 35.4 s |
| 1,000,000 | did not finish in 15 min (v0.10.0 benchmark); 50:36 on the EC2 box | 101.6–110.4 s, 572 MiB |

- **Scaling:** on 1.16.0 the time grew 4.2× per doubling; on 1.18.0 it
  grows 2.2× per doubling, about linear.
- **Plan target met:** A1 asked for 1M rows in under 2 min, with growth of
  no more than 2.3× per doubling.

**Reads are unchanged:** load, eval and show stay within ±5%, which is run
noise; the same steps moved by similar amounts between rounds. Saving one
cell got 11–13% faster, because the save also resolves its cells' keys.

**On the 1M-row store with 1.18.0:**
- `list` (a full load) takes 9.4 s and 1.4 GiB.
- `eval` of a derived measure over all cells takes 10.6 s.
- `set` of one cell takes 17.7 s, made of a full load plus a full save.

Making that single-cell save incremental is plan task B12, raised by the
GUI agent's H3 measurement of an 11 s autosave.

**Compatibility:**
- A store written by 1.16.0 opens, and is edited and saved, with 1.18.0.
- The result reads back with 1.16.0.
- The model file format did not change.
- All 1,211 workspace tests pass on 1.18.0, `cargo deny` is clean, and the
  lockfile change touches only the 17 Mentat crates.
- pg_improv and duckdb_improv don't depend on Mentat.
