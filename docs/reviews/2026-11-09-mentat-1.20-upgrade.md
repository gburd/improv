# Mentat 1.19.1 → 1.20.0 upgrade benchmark — 2026-11-09

The bump takes `mentatdb` 1.20.0 for two reasons:

- **RUSTSEC-2026-0459:** it builds on rusqlite 0.41, which bundles SQLite 3.54.1.
- **Mentat #430:** a long-lived `Store` now sees other connections' commits.

Improv moves to rusqlite 0.41 with it (`crates/cli`, `crates/storage_sql`):
two bundled `libsqlite3-sys` cannot link into one program.

**What changes in Improv:**
- **`ModelStore::fresh_for_write` is gone** (it came in with 7c9479f). Mentat
  now checks SQLite's `data_version` and re-reads its partition map, schema
  and cached values when another connection has committed. Both tests that
  caught the data loss on 1.19.1 pass on 1.20.0 without the workaround:
  `a_reloaded_handle_writes_after_another_process_without_reusing_ids`
  (storage_mentat) and `an_edit_after_another_programs_write_reaches_the_stream`
  (server).
- **`schema_installed` reads `Store::current_schema()`,** the file's schema as
  it is now, not the handle's copy, as Mentat's release notes advise.
- **rusqlite 0.41's `Statement::column_names` returns an iterator:** two call
  sites in storage_sql.
- Mentat's MSRV is now 1.90; Improv's is 1.97.

**Setup:**
- werk: 48 cores, NixOS, release builds. The machine was shared with other
  builds (load 20 to 70), so single runs vary a lot.
- The `improv` CLI was built twice: main (b429e8f: 1.19.1, rusqlite 0.40,
  with the workaround) and this change (1.20.0, rusqlite 0.41, without it).
- `docs/reviews/bench/bench-mentat.sh old new 5`: 5 rounds, alternating A/B
  each round. Medians.

**The large deltas are the machine, not Mentat.** Every step's five runs
overlap widely. For example, re-import 200k ran 19.9–30.8 s on 1.19.1 and
24.6–37.1 s on 1.20.0, and import 100k ran 5.9–20.6 s and 6.1–23.4 s. A
re-run of the two worst steps, 8 rounds alternating and pinned to 4 cores
(`taskset -c 40-43`), at 200k cells:

| Step | 1.19.1 median ms (range) | 1.20.0 median ms (range) | Δ |
|---|---:|---:|---:|
| re-import 200k | 19527 (19078–20973) | 19064 (18716–19454) | −2.4% |
| load + list 200k | 1419 (1354–1677) | 1356 (1307–1411) | −4.4% |

What 1.20.0 adds per operation is one cached `PRAGMA data_version` read per
query or transaction; Mentat measured about 1.3 µs. A reload happens only
after another connection wrote. Removing the workaround saves Improv one
`timelined_transactions` read before each save. Memory and file size are
unchanged.

**Verdict:** no regression. RSS and file size are unchanged; the pinned runs
are within 5%, slightly faster.
