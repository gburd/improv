# Mentat 1.18.0 → 1.19.1 upgrade benchmark — 2026-11-05

The bump takes the newest `mentatdb`. Improv needs nothing new from it; the
upgrade keeps the dependency current before the next release.

**What 1.19 changes, checked against `improv_storage_mentat`:**
- **New `DbErrorKind` variants** (`TempIdNotAnEntity`, `UniqueConflict`)
  and `SimpleAggregationOp::CountDistinct`. Improv matches on neither enum:
  every Mentat error becomes `StoreError::Mentat(e.to_string())`.
- **`"datomic.tx"` names the transaction.** Improv uses no tempids at all
  (no `:db/id` in its transactions, no `tempids` lookups).
- **A tempid used only as a ref value fails.** Improv's refs
  (`:item/category`, `:measure/categories`, `:cell/measure`) are all lookup
  refs, written as `(lookup-ref :category/id N)`, never bare tempids, and
  `:measure/categories` is a vector of them.
- **`sum`, `min` and `max` over mixed longs and doubles return a double;
  a long and an equal double are two values in a set.** Improv's queries
  aggregate nothing, and no attribute holds both longs and doubles.
- **An `:in` value that names no entity matches nothing.** Improv's queries
  take no `:in` inputs. The other behaviour changes are pg_mentat's.

**The stale-handle workaround is still needed.** Mentat 1.19.1 still keeps
the partition map (next entity and transaction ids) in memory and never
re-reads it. With `fresh_for_write` (7c9479f) disabled, both of its tests
fail on 1.19.1:
`a_reloaded_handle_writes_after_another_process_without_reusing_ids`
(storage_mentat) and `an_edit_after_another_programs_write_reaches_the_stream`
(server: "the edit is a new version"). With it, both pass.

**Setup:**
- werk: 48 cores, NixOS, release builds; a shared machine with other
  builds running (load 7 to 25), so single runs vary by up to 40%.
- The `improv` CLI was built twice from the same commit: once against
  `mentatdb` =1.18.0 and once against =1.19.1 from crates.io.
- `docs/reviews/bench/bench-mentat.sh old new 5`: 5 rounds, alternating
  A/B order each round. The table shows medians.

| Step | 1.18.0 ms | 1.19.1 ms | Δ | RSS MiB (old / new) |
|---|---:|---:|---:|---|
| import 100k | 5925 | 6360 | +7.3% | 70 / 70 |
| import 200k | 13368 | 13089 | −2.1% | 120 / 120 |
| re-import 100k | 8626 | 8571 | −0.6% | 197 / 197 |
| re-import 200k | 19585 | 19499 | −0.4% | 372 / 372 |
| set one cell 100k | 468 | 479 | +2.4% | 99 / 99 |
| set one cell 200k | 1097 | 1113 | +1.5% | 176 / 176 |
| load + list 100k | 570 | 574 | +0.7% | 99 / 99 |

**The 100k import's +7.3% is noise.** Its five runs overlap (1.18.0:
5837–6470 ms, 1.19.1: 5988–6687 ms), and the 200k import, which does the
same work twice over, is 2.1% faster. Two re-runs of the 100k import alone:
- 8 rounds, alternating, wall time: 6522 vs 6877 ms (+5.4%), ranges
  6252–7260 and 6202–9518.
- 8 rounds, alternating, pinned to 4 cores (`taskset -c 40-43`), CPU time
  (user + sys): 6.22 vs 6.29 s (**+1.1%**), ranges 6.00–8.03 and 6.08–9.99.

1.19's transactor does one extra pass per transaction
(`check_tx_entity_unique_values`, for unique values asserted on the
transaction entity), over the transaction's own datoms; that is the only
change on the write path Improv uses.

**Everything else is within ±2.5%**, which is run noise. RSS and file
sizes are unchanged.

**Compatibility:**
- A 100k-cell store written by 1.18.0 opens with 1.19.1 and evaluates to
  the same output (checksums of `eval`).
- 1.19.1 then edits it (`set`, `add-derived`), and 1.18.0 reads the result
  back with the same `show` and `eval` output as 1.19.1.
- The model file format did not change.
- The lockfile change touches only the 17 Mentat crates; rusqlite stays
  0.40.2.
- pg_improv and duckdb_improv don't depend on Mentat.
